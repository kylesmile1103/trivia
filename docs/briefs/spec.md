# Part 1 — MISSION SPECIFICATION: Port NetEase Tango (Babel/Antd) to Modern OXC + TypeScript + Vite + Shadcn UI

You are a Principal Systems & Compiler Tooling Engineer. Your objective is to architect and implement an open-source, local-first visual React UI builder by completely replacing the obsolete Babel/CodeSandbox/Ant Design architecture from NetEase Tango (`https://github.com/NetEase/tango`) with a high-performance, deterministic stack powered by OXC (Rust), TypeScript, native Vite dev-server HMR, and un-wrapped Shadcn UI components.

## 1. CONTEXT & ARCHITECTURAL BACKGROUND

### 1.1 The Baseline: NetEase Tango Architecture & Its Fatal Flaws
NetEase Tango demonstrated that Abstract Syntax Tree (AST) manipulation can enable visual editing directly on source code without proprietary DSLs. However, its implementation suffers from 2021-era architectural constraints:
1. **The Sandpack / In-Browser Bundler Bottleneck:** Tango relies on `@codesandbox/sandpack-react` to compile and execute code inside an in-browser iframe. This creates immense memory bloat, breaks when using complex build steps, prevents native Tailwind JIT compilation, and divorces the editor from the developer's real local file system.
2. **Babel / ESTree Sluggishness & Trivia Loss:** Tango uses `@babel/parser`, `@babel/traverse`, and `@babel/types`. Babel is slow on large trees, lacks strong native TypeScript typing, and `@babel/generator` frequently mangles developer formatting, wipes out inline comments, and scrambles JSX spacing.
3. **Runtime Ant Design Wrappers (`@music/tango-ui`):** Ant Design delivers compiled npm artifacts. To make them selectable and editable on canvas, Tango had to create custom wrapper components to capture clicks, attach resize handles, and declare hardcoded property schemas (`prototypes.json`) for inspector controls.

### 1.2 The Target: Native OXC + Vite + Shadcn UI Architecture
You will eliminate every single layer mentioned above:
- **No Sandpack:** Run a real, native local Vite dev server in the user's workspace. Embed it into the editor via a standard `<iframe>`. Let Vite handle HMR and Tailwind JIT natively.
- **No Babel:** Replace Babel with a high-performance Rust engine using `oxc` crates (`oxc_allocator`, `oxc_parser`, `oxc_ast`, `oxc_codegen`, `oxc_traverse`). Mutations happen in microseconds, preserving comments and formatting.
- **No Component Wrappers:** Use Shadcn UI (`src/components/ui/`). Because developers own the raw `.tsx` source code in their project, there is zero runtime wrapping. A Vite build plugin injects non-invasive source coordinates (`data-ast-node`), while an independent interaction layer over the iframe manages hover boxes, bounding rectangles, and drag handles. Dynamic component inspector forms are generated by statically analyzing the TypeScript `Props` interfaces of the Shadcn components.

## 3. CORE SUBSYSTEM SPECIFICATIONS

### Phase 1: Dev-Server AST Locator Plugin (`packages/vite-plugin-ast-locator`)
Create a custom Vite plugin that transforms `.tsx` files in development mode only:
1. Intercept `.tsx` files inside Vite's `transform(code, id)` hook (excluding `node_modules`).
2. Parse the TSX source into an AST using OXC.
3. Traverse every `JSXOpeningElement`.
4. Generate a deterministic breadcrumb locator attribute:
   - **Format:** `<relative_path>#<component_or_export_name>#<depth_index_path>`
   - **Example:** `src/pages/Dashboard.tsx#Dashboard#0.1.3`
   - *Explanation:* In `Dashboard`, index `0` is the root JSX element (e.g. `<Card>`), child `1` is `<CardContent>`, and child `3` is `<Button>`.
5. Inject this attribute into the tag:
   ```tsx
   // Transformed in memory during Vite dev:
   <Button data-ast-node="src/pages/Dashboard.tsx#Dashboard#0.1.3" variant="outline">
     Click Me
   </Button>
   ```
6. Return transformed code with source maps intact.

### Phase 2: Rust / OXC AST Mutation Engine (`crates/tango_oxc_engine`)

Implement a standalone Rust library leveraging official `oxc` crates.

#### Memory Management & Arena Lifecycle

OXC syntax nodes exist inside an `oxc_allocator::Allocator`. Every mutation pipeline follows this pattern:

1. Initialize a fresh `Allocator`:
   ```rust
   let allocator = Allocator::default();
   let source_type = SourceType::from_path(file_path).unwrap().with_typescript(true).with_jsx(true);
   let ret = Parser::new(&allocator, &source_code, source_type).parse();
   let mut program = ret.program;
   ```
2. Parse the locator breadcrumb path to traverse directly to the target `JSXElement` node.
3. Execute the requested atomic mutation:
   * **`insert_child(locator, position, snippet_or_component)`:**
     * Build a new `JSXElement` using `oxc_allocator`.
     * Insert into the target parent's `children: ArenaVec<'a, JSXChild<'a>>` at the requested index.
     * Call `import_manager` to check if `import { <Component> } from "@/components/ui/<component>"` is present. If missing, construct an `ImportDeclaration` and prepend it to the root `program.body`.
   * **`update_prop(locator, prop_name, prop_value_json)`:**
     * Walk the `JSXOpeningElement.attributes`.
     * If the attribute exists, update its value. If not, construct and insert a new `JSXAttributeItem::Attribute`.
     * Value mapping: Strings become `JSXAttributeValue::StringLiteral`. Booleans (`true`/`false`), numbers, and objects become `JSXAttributeValue::ExpressionContainer`.
   * **`remove_node(locator)`:**
     * Remove the target node from its parent's `children` arena vector.
     * Scan the remaining AST. If no other JSX element references this component name, purge the corresponding import statement.
   * **`move_node(source_locator, target_parent_locator, target_index)`:**
     * Extract the existing node without data loss and transplant it into the destination container's children array.
4. Serialize back to TypeScript source code using `oxc_codegen`:
   ```rust
   let result = CodeGenerator::new()
       .with_options(CodegenOptions {
           preserve_parens: true,
           ..Default::default()
       })
       .build(&program);
   let mutated_source = result.source_text;
   ```
5. Perform an atomic file write (`write-to-temporary-file -> rename`) so the local OS triggers a single file-system change event, causing Vite to instantly HMR the update into the canvas.

## 3. Core Engine Mechanics: Babel to OXC Migration

OXC differs from Babel in one crucial architectural dimension: Memory Arenas (`oxc_allocator::Allocator`).

In Babel, AST nodes are mutable JavaScript reference objects. In OXC, syntax nodes are allocated inside a bump-allocated memory arena (`oxc_allocator`) to maximize CPU cache locality. When mutating an OXC AST, you cannot simply mutate objects across different scopes without using the allocator to create and insert new nodes.

### AST Locator Specification

Instead of Tango's arbitrary IDs, construct a deterministic AST Locator string:
`[RelativeFilePath]#[ComponentExportName]#[BreadcrumbNodeIndex]`
Example: `src/views/CustomerCard.tsx#CustomerCard#0.1.3`

- `0`: Root JSX Element (e.g., `<Card>`)
- `1`: Second child of Root (e.g., `<CardContent>`)
- `3`: Fourth child of `<CardContent>` (e.g., `<Button>`)

### The Rust AST Mutation Operations

Your OXC engine must implement four atomic operations using `oxc_ast::ast::*`:

**InsertJsxChild(target_locator, position, new_element_json):**
- Uses `oxc_parser::Parser` to parse the incoming snippet or builds the `JSXElement` node directly via `oxc_allocator`.
- Traverses to the target element's `children: ArenaVec<'a, JSXChild<'a>>`.
- Inserts the new child at the designated array index.
- Scans the file's top-level import statements; if the Shadcn component isn't imported, constructs an `ImportDeclaration` and appends it to the AST.

**UpdateJsxAttribute(target_locator, prop_name, prop_value_json):**
- Traverses to the target `JSXOpeningElement`.
- Finds or inserts a `JSXAttributeItem::Attribute`.
- Converts the JSON value into either a `JSXAttributeValue::StringLiteral` (for simple strings) or `JSXAttributeValue::Element` / `ExpressionContainer` (for booleans, expressions, numbers).

**MoveJsxNode(source_locator, target_parent_locator, target_index):**
- Extracts the node from the source container's children vector.
- Inserts it into the destination container's children vector.

**RemoveJsxNode(target_locator):**
- Removes the node from its parent's children vector.
- Cleans up unused Shadcn imports if no other AST nodes reference that component name.

## 4. Replacing Antd Wrappers with Shadcn UI

Tango wrapped Antd components because it needed to:
- Capture mouse events on canvas.
- Provide a static property schema (`prototypes.json`) to render the right-hand Inspector Panel.

With Shadcn, you avoid wrappers by separating DOM Interaction from Component Definition:

### 1. Zero Runtime Wrappers on DOM Elements

Do not wrap Shadcn components inside React wrapper components.
Instead, the Vite plugin injects `data-ast-node` into every JSX opening tag:

```tsx
// Before Vite transform:
<Button variant="outline" size="sm">Click</Button>

// After Vite transform (in-memory dev only):
<Button data-ast-node="src/views/Home.tsx#default#0.2.1" variant="outline" size="sm">Click</Button>
```

On the host canvas, an absolutely positioned SVG/HTML Selection Overlay Layer hovers over the iframe. When the user moves their mouse over the canvas:
- `document.elementsFromPoint(e.clientX, e.clientY)` inside the iframe finds the innermost element containing a `data-ast-node` attribute.
- The host canvas reads this attribute and renders the blue selection bounding box on top of the iframe.
- Drag-and-drop handles, spacing margins, and padding overlays are drawn entirely on the host canvas layer—the underlying Shadcn component remains unpolluted.

### 2. Dynamic Prop Schema Extraction

Instead of writing manual `prototypes.json` files for Shadcn:
- Run an OXC/TypeScript static analyzer across `src/components/ui/*.tsx`.
- For `button.tsx`, parse the `ButtonProps` interface:
  ```tsx
  export interface ButtonProps extends React.ButtonHTMLAttributes<HTMLButtonElement>,
    VariantProps<typeof buttonVariants> {}
  ```
- Extract the variant union types:
  `variant?: "default" | "destructive" | "outline" | "secondary" | "ghost" | "link"`
  `size?: "default" | "sm" | "lg" | "icon"`

The host app automatically maps string unions to a SelectSetter, booleans to a SwitchSetter, and strings to an InputSetter inside the properties panel.
